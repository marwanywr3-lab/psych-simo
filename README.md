# محاكي الطبيب النفسي — مستشفى د. مروان باربود

لعبة قصصية ثابتة الصور، عربية RTL وإنجليزية LTR، مبنية بـReact وTypeScript وVite. يكتب اللاعب جميع محادثاته مع مرضى بالغين خياليين ونوره والمدير بحرية. Gemini الحقيقي يولّد الشخصيات والحوار والمراجعات. لا توجد ردود مرضى محلية وهمية في التطبيق.

## التشغيل

يتطلب Node.js 22.12 أو أحدث (يستخدم النشر Node 24).

```bash
npm ci
npm run dev
npm run typecheck
npm test
npm run test:e2e
npm run build
npm run preview
```

للاختبار محليًا يضبط `playwright.config.ts` Chromium على `/usr/bin/chromium`. إن لم يكن موجودًا، ثبّت Chromium أو احذف `executablePath` ثم شغّل `npx playwright install chromium`. في CI يستخدم Playwright متصفحه تلقائيًا.

## Gemini والمفتاح الشخصي

من «الإعدادات» أدخل مفتاحك، اختر النموذج ثم «اختبار الاتصال». لا تضع المفتاح في المستودع أو Actions أو عنوان URL أو محادثة الدعم. يبقى في الذاكرة افتراضيًا؛ اختيار الحفظ يضعه في localStorage على جهازك فقط. يمكن حذفه فورًا، ولا يدخل تصدير المسيرة. الإرسال من المتصفح مباشرة إلى Google عبر `x-goog-api-key`.

الخياران الافتراضيان `gemini-3.5-flash-lite` و`gemini-3.8-flash`، مع اسم قابل للتعديل. الاختبار يجلب `models.list` بحسب مفتاحك، ثم يختبر ردًا منظمًا؛ لا يفترض إتاحة أي نموذج ولا يبدّله تلقائيًا. إن فشل النموذج، يمكن اختيار نموذج ظاهر في القائمة أو إدخال اسم آخر. كل اختبار اتصال يولّد طلبًا صغيرًا يُحسب ضمن حصة Google. الاستخدام ليس مجانيًا بلا حدود؛ التطبيق لا يفعّل فوترة ولا ينشئ موارد.

التكامل يتبع الوثائق الرسمية التي فُحصت بتاريخ 2026-10-13:

- [Structured outputs](https://ai.google.dev/gemini-api/docs/structured-output)
- [Interactions API](https://ai.google.dev/api/interactions)
- [Models API](https://ai.google.dev/api/models)

يستخدم `POST /v1beta/interactions` مع `system_instruction` و`response_format` وJSON Schema مشتق من Zod، و`store:false`. يقرأ `steps[].content` من مخرجات النموذج؛ ويقبل شكل `outputs` للإصدارات الأقدم. لا يرسل الصور. المراجعة بدرجة حرارة صفر، والحوار بدرجة 0.65. لا توجد إعادة محاولة خفية أو تبديل تلقائي للنموذج؛ المهلة 60 ثانية، و429 يفرض انتظارًا قبل المحاولة اليدوية. رسائل الخطأ لا تعرض محتوى المفتاح أو جسم الطلب. الموديل يحتاج دعم Interactions والرد المنظم؛ نجاح `models.list` وحده ليس ضمانًا.

## الصور الأصلية

ثلاثة مشاهد فقط داخل `public/assets/scenes`؛ حُوّلت ملفات JPEG الأصلية إلى PNG دون قص أو تغيير أبعاد أو تعديل بكسلات الصورة المفكوكة، لتطابق الأسماء المطلوبة:

| الملف | محتوى المرفق الأصلي |
|---|---|
| `attendance.png` | `4-1000089216.jpg`، جهاز البصمة وباب يسار الصورة |
| `corridor.png` | `2-1000089218.jpg`، الممر والأبواب؛ خلفية القائمة أيضًا |
| `clinic.png` | `3-1000089217.jpg`، المكتب والكرسي البني |

استُبعد مرفق واجهة المبنى. لا صور شخصيات ولا خلفيات مولّدة. الأصول 1280×720، ومناطق الضغط نسبية في `src/scenes/assets.ts` فوق حاوية 16:9 دون قص أثناء اللعب. نص البصمة داخل شاشة الجهاز واللافتة فوق أقرب باب يمين الممر. الخط العربي مضمن محليًا، بلا طلب خطوط خارجي.

## قواعد اليوم والجلسات

- تبدأ الساعة المخزنة 10:00. الحضور مرة واحدة، ثم الباب الأيسر فالممر فالعيادة.
- سعة اليوم عشوائية 2–5 وثابتة بعد الحفظ. تُعطى الأولوية للمتابعات المستحقة، ويُعاد جدولة الزائد لليوم التالي مع سجل واضح.
- يجري تجهيز المرضى الجدد دفعة واحدة. تُحفظ كل نتيجة تجهيز ناجحة قبل الطلب التالي، فلا تضيع عند انقطاع الشبكة. الهوية والقصة الأساسية منفصلتان عن الحالة المتغيرة.
- الكلام الناجح يضيف 7 دقائق، والانتقال دقيقتين، واعتماد الإغلاق 5 دقائق، والاستراحة 15 دقيقة. القواعد في `src/game/time.ts`.
- الكتابة وانتظار الشبكة والإعدادات وإعادة المراجعة المرفوضة لا تقدّم الوقت. الرسالة الفاشلة محفوظة وتُعاد بنفس المعرف.
- المراجعة تستند إلى الأهداف الأصلية والأدلة، وتحافظ على المريض والحوار إن رفضت. لا يلزم الشفاء. عند القبول تُحفظ الخطة والملخص والموعد مرة واحدة.
- بعد انتهاء المرضى، «استكمال أعمال اليوم» ينقل الساعة إلى 18:00، ثم العودة للبصمة. وقت الرجوع نفسه يُحسب، ولذلك يمكن أن يسجل التقرير 18:04. يمكن إكمال الجلسات بعد 18:00 دون إغلاق قسري.
- لا توجد زيادة صعوبة حسب اليوم. العودة تحافظ على معرف المريض وهويته وتاريخه مع تطور مرتبط بالخطة السابقة.
- نوره محادثة منفصلة وتنبيهاتها تستخرج مع رد المريض وتُحفظ مع معرّفات وأسباب وحالة معالجة.

## المدير والإنذارات

يرشح Gemini واقعة محددة فقط للإساءة اللفظية أو الإهمال الصريح، ويشترط الكود رسالة فعلية من الطبيب واقتباسًا مطابقًا ومعرفًا غير مكرر. يوضع الاستدعاء بعد انتهاء الجلسة، ثم يجري طلب مستقل لمراجعة الأدلة ورد الطبيب. لا تطبق عقوبة قبل وجود رد وتقييم مكتمل. يمكن إسقاط الواقعة لسوء فهم.

السلم حتمي في الكود: تنبيه إداري ← إنذار أول ← إنذار نهائي ← فصل. لا يمكن للذكاء الاصطناعي تعيين مستوى العقوبة، ولا تُحسب الواقعة مرتين. رفض إنهاء الجلسة وطلب نوره وبطء الكتابة ومشكلات API وعدم شفاء المريض ليست مخالفات. يبقى سجل المسيرة المفصولة قابلًا للمراجعة.

التحقق البنيوي وقواعد الأدلة تقللان أخطاء النموذج؛ لا يضمن أي prompt امتناع النموذج عن كل خطأ أو محاولة تلاعب. الكلام لا يملك وصولًا إلى reducer أو المفاتيح أو التخزين.

## الحفظ والخصوصية

IndexedDB يحفظ المسيرة كاملة ومعرّف الملف النشط في معاملة واحدة بعد كل تغيير. يشمل المرضى والمحادثات والمسودات والملاحظات والأيام والوقت والمراجعات والتنبيهات والاستدعاءات. تصغير المحادثة أو تغيير المشهد لا يعيد التوليد. عند إعادة التحميل تصبح الرسالة المعلقة قابلة لإعادة المحاولة، وتعود المراجعة المعلقة إلى جلسة نشطة.

«لعبة جديدة» تعرض تأكيدًا وتنشئ ملفًا مستقلًا دون حذف القديم. «المسيرات» يعيد أي ملف. التصدير JSON لا يحتوي المفتاح؛ الاستيراد يتحقق من الإصدار والبنية ومراجع المرضى والجلسات والجدول ويستورد نسخة مستقلة. نسخة المخطط الحالية 2، مع ترحيل نسخة 1. يُرفض إصدار أحدث بدل تخمينه. احفظ نسخة تصدير قبل مسح بيانات المتصفح. التخزين محلي وغير مشفر، والمحادثات تُرسل إلى Google لتنفيذ المهام؛ لا تستخدم معلومات مرضى حقيقيين.

## البنية

- `src/scenes`: صور المشاهد ومناطق التفاعل.
- `src/components`: الساعة والنوافذ والمحادثة.
- `src/game/reducer.ts`: آلة الحالات والتحولات المعتمدة.
- `src/game/time.ts`, `scheduling.ts`, `discipline.ts`: قواعد ثابتة مستقلة عن AI.
- `src/game/schemas.ts`, `persistence.ts`: تحقق البيانات وIndexedDB والترحيل.
- `src/ai/client.ts`, `service.ts`: اتصال Gemini وتجهيز البيانات والسياق.
- `src/ai/prompts`: ست مهام منفصلة قابلة للمراجعة.
- `tests`: اختبارات قواعد وAPI ومتصفح. المحاكاة الشبكية موجودة في الاختبارات فقط.

## GitHub Pages

ملف `.github/workflows/pages.yml` يفحص الأنواع والقواعد والمتصفح ثم يبني وينشر. من إعدادات المستودع **Pages → Source → GitHub Actions**. الدفع إلى `main` يشغّل النشر، أو شغّله يدويًا من Actions.

يضبط البناء `VITE_BASE_PATH` إلى `/اسم-المستودع/` (أو `/` لمستودع `*.github.io`). محليًا يستخدم `./`. لا يوجد موجّه مسارات URL، لذا إعادة التحميل لا تسبب خطأ مسار على Pages. الموقع ثابت، لا خادم أو DNS أو موارد مدفوعة ولا أسرار في Actions.

## حدود التحقق

اختبارات المتصفح تستخدم mock واضحًا لـGemini وتغطي الحضور والمشهد والجلسة وفشل الطلب وإعادة المحاولة ورفض الإنهاء وقبوله والحفظ والخروج واليوم التالي، على أربعة مقاسات. اختبار Gemini الحقيقي يتطلب مفتاح المستخدم من داخل اللعبة؛ لا يمكن الجزم بإتاحة نموذج لمفتاح لم يُدخل. اللعبة عن خيال قصصي، وليست خدمة علاج أو تدريبًا طبيًا معتمدًا.
